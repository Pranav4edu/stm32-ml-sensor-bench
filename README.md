# STM32 ML Sensor Benchmark

An on-device machine-learning benchmark lab for the STM32 NUCLEO-F446RE.

The goal is to build a small real-time sensor classifier, write and optimize its inference kernels by hand, then compare the result on identical inputs against:

- a clear fixed-point C reference implementation;
- a Cortex-M4-optimized implementation;
- TensorFlow Lite for Microcontrollers; and
- ST's X-CUBE-AI toolchain.

## Hardware

- STM32 NUCLEO-F446RE
- Built-in ST-LINK programmer/debugger
- Built-in green LED and user button
- Future addition: an I2C/SPI IMU breakout for live motion data

Until an IMU is attached, deterministic synthetic accelerometer windows are used. This keeps the inference and benchmark work reproducible on the board from the first commit.

## Measurement principles

Every engine will receive the same quantized model weights and test inputs. We will record:

- DWT CPU cycle count and latency;
- flash and RAM use;
- output agreement with golden test vectors; and
- model accuracy after live-sensor integration.

UART logging runs at 115200 baud through the NUCLEO's ST-LINK virtual COM port. It is kept outside the timed inference section.

## Roadmap

1. Establish build, flash, UART, LED, and cycle-counter baseline.
2. Add synthetic sensor windows and a fixed-point reference classifier.
3. Add hand-optimized kernels and benchmark CSV output.
4. Import equivalent TensorFlow Lite Micro and X-CUBE-AI models.
5. Add a physical IMU, collect data, train, and evaluate live inference.

## Build

This project is generated by STM32CubeMX and uses CMake. Open the folder in VS Code with STMicroelectronics' STM32CubeIDE for Visual Studio Code extension, select the Debug CMake preset, and build/flash using the ST-LINK tools.

The CubeMX configuration is stored in `button_blinker.ioc`. Edit pins and peripheral configuration there, regenerate, and keep application changes inside the `USER CODE` sections of generated sources.
